# 开发环境与配置说明

本文档说明多域 LLM 微调与评测平台（`llm-platform`）的开发环境、部署链路与全部配置项。面向**要在本机或云端跑起来 / 改配置 / 排环境问题**的人。功能层面的使用说明见 [README.md](./README.md)。

---

## 1. 项目定位与技术栈

一条闭环：**选领域 → 处理数据 → LoRA 微调 → 保存权重 → 复用对话 → 多维度评测 → 跨领域对比**。

| 层 | 技术 | 说明 |
|---|---|---|
| UI / 服务 | **Gradio 5** | 工作台 + 流式对话，`app.py` 启动 |
| 模型 | **Qwen2.5-7B-Instruct** | 基座模型，HuggingFace / ModelScope 双路径 |
| 框架 | **PyTorch + Transformers + Accelerate** | 量化版另需 bitsandbytes；LoRA 用 PEFT（后续 Sprint） |
| 数据处理 | **pandas / numpy**（纯 CPU） | 不加载 LLM，可本地无卡跑 |
| 领域预设 | **JSON 资源 + 阶段化引擎** | 资源即知识，改 JSON 不改代码 |

> 注：`hf_transfer`（加快首次下载）、`safetensors` 也安装在云端；PEFT / datasets / evaluate 等为后续 Sprint 预留，本期不装。

## 2. 两个开发环境

本项目**不用一个环境跑全部**，而是刻意分两块：

| | 本机（Windows, CPU-only） | 本机 + NVIDIA GPU | 云端（AutoDL, GPU） |
|---|---|---|---|
| 用途 | 写代码、纯 CPU 数据处理管道验证 | 加载模型、流式对话 | 加载模型、流式对话、训练 |
| 能否对话 | ❌ 无 GPU | ✅（`setup_local.bat` + `run_local.bat`，见 §2.3） | ✅ |
| 能否数据处理 | ✅ | ✅ | ✅ |
| 包管理器 | `.venv-verify`（轻量，pandas/numpy） | `.venv-local`（torch/transformers/bitsandbytes） | 系统 conda `base` + `requirements.txt` |

- **系统 Python**：`C:\Users\m1887\AppData\Local\Programs\Python\Python313`（Python **3.13.7**）。
- **轻量 venv**：`D:\claude\llm-platform\.venv-verify\`，单独建、几十 MB，只装了 `pandas==3.0.5`、`numpy==2.5.2`。用于**纯 CPU 管道改动本地快速验证**，不必挂卡、不必连云：

- **镜像**：PyTorch **2.8 / CUDA 12.8 / Python 3.12**，自带 CUDA 版 torch —— **不要重装 torch**（`requirements.txt` 里 torch 被注释掉，就是这个原因）。
- **conda**：非交互 SSH 默认不激活；所有远程命令都要先激活：

  ```bash
  source /root/miniconda3/etc/profile.d/conda.sh && conda activate base
  ```

- **数据盘路径**：`/root/autodl-tmp/llm-platform`（数据盘持久、大、换镜像不丢）。权重缓存放 `hf/`，见 `HF_HOME`。
- **无卡也能启动**：`app.py` 的 `warm_up()` 失败会被捕获，纯 CPU 功能（数据处理）可用；只有对话/训练 Tab 需挂 GPU 卡（RTX 3090/4090/A100）。

### 2.3 本机 + NVIDIA GPU（第三种环境，可选）

有独立 NVIDIA 显卡且已下模型的机器，可**不连云**直接本地跑对话。模型路径与量化走环境变量（`MODEL_NAME` / `QUANTIZATION` / `FORCE_DEVICE`），不污染云端默认。

```bat
setup_local.bat                                  rem 一次性：建 .venv-local（torch-CUDA + requirements + bitsandbytes）
set MODEL_NAME=D:\models\Qwen2.5-7B-Instruct     rem 本地模型目录（或填进 run_local.bat）
run_local.bat                                    rem 启动（内部设 QUANTIZATION=4bit）→ http://127.0.0.1:7860
```

> ⚠️ 仅在有 GPU 的机器运行；本机（CPU-only）请跳过，规避 setup_local 触发的大体积 torch 下载。`.venv-verify` 与本方法互不影响。
> 显存参考：7B fp16 权重 ≈15.2GB，12GB 显卡需 4bit（≈4.2GB）或 8bit（≈7.6GB）。

## 3. 目录结构（配置相关）

```
llm-platform/
├── app.py                 # 入口：build_app + warm_up + demo.queue().launch(127.0.0.1:7860)
├── config.py              # ★ 唯一配置源（见 §4.1）
├── requirements.txt       # 云端运行依赖（torch 注释，因镜像自带）
├── run.sh                 # AutoDL 一键启动（补装依赖 + python app.py）
├── start_app.sh           # 云端后台启动（setsid 脱离会话，由 deploy.sh start 调用）
├── run.bat                # 本机提示脚本
├── deploy.sh              # 本机 ⇄ 云端一键：ssh 让云端 git clone/pull 同步代码 / 装依赖 / 后台启动 / 看日志
├── data/                  # 数据处理产物（sharegpt jsonl/json + config.json）← gitignore
├── samples/               # 示例数据（仅开发测试，不进 UI）
├── resources/             # ★ 领域预设资源（知识即数据，见 §4.3）
└── llm_platform/
    ├── model_manager.py   # 懒加载单例 load_model()，设备/精度探测
    ├── chat.py            # 对话管线：apply_chat_template + generate + 流式
    ├── domain.py          # 领域注册表：labels / slug / default_preset_name
    ├── data_pipeline/     # 数据处理门面（run_pipeline）
    └── domain_presets/    # 阶段化领域预设引擎
```

几个关键路径的解析方式：

- `config.py` 用 `PROJECT_ROOT = Path(__file__).resolve().parent` 定位 `data/`、`resources/`。
- `data_pipeline/io.py` 用 `parents[2]` 回到项目根拿 `data`；`domain_presets/resources.py` 用 `parents[2]` 拿 `resources`。**二者与 `config.py` 的路径等价**，同指本项目根。

## 4. 配置说明

### 4.1 `config.py` —— 唯一配置源

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `MODEL_NAME` | `"Qwen/Qwen2.5-7B-Instruct"` | 基座模型 repo id；**可用环境变量 `MODEL_NAME` 覆盖**。云端脚本会改成本地 ModelScope 路径 |
| `MODEL_SHORT_NAME` | 取 `MODEL_NAME` 最后一段 | 展示用 |
| `FORCE_DEVICE` | `None`（自动探测） | `"cuda"` 强制 / `"cpu"` 仅本机调试（7B 极慢或报错）；**已接线到 `_pick_device()`**（优先认它） |
| `QUANTIZATION` | `"none"` | `"none"` / `"8bit"` / `"4bit"`（8bit/4bit 需 bitsandbytes + GPU；12GB 跑 7B 用 4bit）；**可用环境变量覆盖** |
| `DEFAULT_DEVICE_MAP` | `"auto"` | 传给 `from_pretrained(device_map=...)` |
| `GENERATION` | `max_new_tokens=1024, do_sample=True, temperature=0.7, top_p=0.9` | 对话 Tab 生成参数 |
| `APP_TITLE` | `"多域 LLM 微调与评测平台"` | 界面标题 |
| `DOMAINS` | 医疗/法律/金融/教育（含描述） | 领域下拉列表 `<label, desc>` |
| `DOMAIN_SLUGS` | 医疗→medical 等 | 中文标签 → 资源目录 slug |

> `FORCE_DEVICE` 目前**没有**在 `model_manager` 里被消费——`_pick_device()` 直接看 `torch.cuda.is_available()`。若想强制 CPU，需要手动改 `model_manager`。

### 4.2 环境变量（跨脚本生效）

| 变量 | 设在哪 | 作用 |
|---|---|---|
| `MODEL_NAME` | `run.sh` / `start_app.sh` / `run_local.bat` | 云端改为本地 ModelScope 权重路径 `/root/autodl-tmp/llm-platform/models/Qwen2.5-7B-Instruct`（云端无 huggingface 访问）；本机 +GPU 用本地模型目录 |
| `QUANTIZATION` | `run_local.bat`（或启动前 set） | `"none"`/`"8bit"`/`"4bit"`；本机 4bit 跑 7B；云端不设则默认 `"none"` |
| `FORCE_DEVICE` | 启动前 set（本机调试） | `"cuda"`/`"cpu"` 强制设备；不设则自动探测 |
| `HF_HOME` | `run.sh` / `start_app.sh` | 权重缓存落数据盘 `/root/autodl-tmp/llm-platform/hf` |
| `SSH_ALIAS` | `deploy.sh` 默认 `autodl` | 对应 `~/.ssh/config` 里的 Host（含 host/port/key） |
| `HF_ENDPOINT` | `run.sh` 注释掉 | 如需从 HF 拉权重可临时设 `https://hf-mirror.com`（学术加速是控制台手动开关，脚本开不了） |

**SSH 别名**：`~/.ssh/config` 里已配好 `autodl`（HostName `connect.bjb2.seetacloud.com`，Port `23296`，Identity `~/.ssh/autodl_ed25519`）。

### 4.3 领域预设资源（`resources/`）= 配置即数据

领域知识以 JSON 存放，由引擎解释；**改资源即改规则，无需改代码**。

```
resources/
├── _shared/         deid.json / units.json   ← 基础表，默认合并
├── medical/         sections / deid / terms / units / qc / preset   ← 深参考
├── legal/           deid / sections / terms / structure / citation / qc / preset
├── finance/         numeric / qc / preset
└── education/       options / qc / preset
```

- **`preset.json`** = 该领域阶段编排配置：`{name, stages:[{kind, ...params}]}`。`kind` 必须是 `STAGE_REGISTRY` 里的键（见下）。
- **合并策略**：`_shared` 为默认，领域文件**覆盖同名表**。所有正则在此一次性编译并缓存（`ResourceBundle.load`）。
- 表名集合（`TABLE_NAMES`）：`deid / sections / terms / units / qc / structure / citation / numeric / options`。

**阶段注册表**（`domain_presets/__init__.py` 的 `STAGE_REGISTRY`）：

```
deid  section  terminology  units  completeness_qc  quality_score
marker_norm  numeric              # stages_generic
doc_type  legal_structure         # stages_legal
```

加新阶段：在 `stages_generic.py` 加 `Stage` 子类 → 注册进 `STAGE_REGISTRY` → 在 `preset.json` 的 `stages` 加 `{"kind":"名字"}`。

> ⚠️ 法律领域**不要用 `section` 阶段**（会重写文书、丢法院名/类型）；分部改由 `LegalStructureStage` 非破坏性记录。

### 4.4 `requirements.txt` —— 版本钉死的原因

```txt
transformers==4.53.1
gradio==5.12.0
pydantic==2.10.6       # 钉 <2.11：修复 Gradio 5.12 与 Pydantic 2.11+ 的 schema 解析崩溃
accelerate==1.2.1
hf_transfer==0.1.7     # 加快首次模型下载
safetensors==0.4.5
# torch 注释：镜像自带 CUDA torch，勿重装
# bitsandbytes / peft / datasets / evaluate：后续 Sprint
```

- **版本冲突**：AutoDL 镜像 torch 较旧时，去掉 `transformers` 版本号再 `pip install -U transformers gradio accelerate`。
- **pydantic 钉 `2.10.6`**：Gradio 5.12 与 pydantic 2.11+ 有 schema 解析 bug；也可改用 `gradio>=5.23.1`。

## 5. 开发 / 部署工作流

### 5.1 一键部署循环（本机 ⇄ 云端）

代码不经本地直传，统一走 GitHub 远程仓库：本机 `git push origin main` 后，`./deploy.sh` 通过 ssh 让云端 **浅克隆 + 稀疏检出**（`--depth=1` + `git sparse-checkout`，仅拉运行所需、排除文档等）到 `/root/autodl-tmp/llm-platform`。

在 `D:\claude\llm-platform` 下：

```bash
git push origin main    # 先把本地改动推到远程仓库
./deploy.sh            # 云端 git pull 同步代码 + 装依赖（不重装 torch）
./deploy.sh start      # 云端后台启动 app（需已挂 GPU 卡）
./deploy.sh logs       # 看云端日志（tail -n 100 app.log）
# 实时日志: ssh autodl 'tail -f /root/autodl-tmp/llm-platform/app.log'
```

实现要点（`deploy.sh`）：
- 同步走 ssh 远端 git，**浅克隆 + 稀疏检出**：`--depth=1` 只拉最新快照；`git sparse-checkout` 仅检出云端运行所需顶层路径（白名单 `SPARSE_PATHS`，默认 `app.py config.py requirements.txt run.sh start_app.sh llm_platform resources`），**docs/、README.md、CLAUDE.md、LICENSE、tests/、samples/、*.bat、deploy.sh 等不检出**，云端目录更精简。远端 `$REMOTE_DIR/.git` 存在则 `git fetch --depth=1` + `reset --hard origin/<branch>` + 重设 sparse；否则 `git clone --depth=1 --sparse`。仓库/分支/白名单可用 `GIT_REPO` / `GIT_BRANCH` / `SPARSE_PATHS` 环境变量覆盖。
- 远程先激活 conda 再 `pip install -r requirements.txt`。
- `start` 走 `start_app.sh`：`setsid nohup ... > app.log 2>&1 < /dev/null &`，真正脱离 SSH 会话，避免断开被 SIGHUP 杀掉；先 `pkill -f "python app.py"` 旧实例。

### 5.2 启动链路

`run.sh`（前台，手动跑）/ `start_app.sh`（后台，deploy.sh start 调用）→ `python app.py`：

```python
demo = build_app()
warm_up()                      # 预热/下载权重；失败仅告警不阻断
demo.queue()                   # 流式必需
demo.launch(server_name="127.0.0.1", server_port=7860, share=False)
```

**绑定 `127.0.0.1` 而非 `0.0.0.0`**：靠本机 SSH 端口转发访问，避免容器内 0.0.0.0 绑定导致的 Gradio 回环自检失败。

### 5.3 本机访问（端口转发，不占 GPU）

```bash
ssh -N -L 7860:localhost:7860 autodl
# 浏览器打开 http://localhost:7860
```

## 6. 常见环境问题排查

| 现象 | 原因 / 处理 |
|---|---|
| `CUDA 不可用` | 无 GPU 机器。聊天/训练需 AutoDL GPU 实例；数据处理纯 CPU 无需 |
| 应用能启动但点对话报错 | 预期——无卡时数据处理可用，对话需挂卡 |
| 首次权重下载慢 | AutoDL 控制台开「学术加速」（脚本无法自动开）；或临时设 `HF_ENDPOINT=https://hf-mirror.com` |
| 版本冲突（transformers/torch） | 去 `transformers` 版本号再 `pip install -U transformers gradio accelerate` |
| 本地改代码要上云 | `git push origin main` 后 `./deploy.sh`（云端 git pull 同步 + 装依赖）+ `./deploy.sh start` 重启；`./deploy.sh logs` 看日志 |
| Windows 打印中文乱码 | `set PYTHONIOENCODING=utf-8` |
| 导入 `model_manager` 在本机报 torch 缺失 | 属预期——本机 `.venv-verify` 无 torch/transformers，这些模块只在云端 import |
